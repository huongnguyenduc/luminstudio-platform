# US-017 Admin Product HTTP API

## Status

implemented

## Lane

normal

## Product Contract

The Go API exposes the first administrator product creation endpoint on top of
the Phase 2 product persistence foundation. `POST /admin/products` accepts the
v1 product draft JSON shape, validates it at the HTTP boundary, creates a
server-side product identity, persists the product through PostgreSQL-backed
product storage, and returns the created product record.

This story does not add admin UI behavior, MinIO uploads, NATS publication or
consumption, worker processing, search synchronization, authentication,
authorization, product update/delete workflows, or live K3d platform proof.

## Acceptance Criteria

- `services/api-gateway` routes `POST /admin/products` through the existing
  standard-library HTTP server without introducing a new web framework.
- The endpoint parses one JSON product draft, rejects malformed JSON, unknown
  trailing JSON, and invalid product drafts before persistence.
- The endpoint creates a server-side `prod_` identity that matches the v1
  product ID contract and persists through the existing product store.
- Successful creation returns HTTP 201 and a JSON `ProductRecord`.
- Verification proves native Go tests, Bazel tests, route wiring, product
  handler behavior, and story non-goals without requiring live K3d services.
